Getting started /

Quick start

Run Gresbase with Docker Compose and connect it to your PostgreSQL database in a few minutes.

On this page

    Before you start#

    • Docker with Compose v2 (docker compose version should answer).
    • A PostgreSQL database the container can reach, and a user to connect with.

    If PostgreSQL runs on the same machine but outside Docker, localhost inside the container is not your machine. Use host.docker.internal on Docker Desktop, or the host’s IP address.

    Install and start#

    1. Create the Compose file#

      Save this in an empty folder. If you don’t use Compose, the docker run tab does the same in one command.

      services:
  gresbase:
    image: ghcr.io/OWNER/gresbase:latest
    restart: unless-stopped
    environment:
      DATABASE_URL: postgres://USER:PASSWORD@HOST:5432/DBNAME
      GRESBASE_READ_ONLY: "false"
    volumes:
      - gresbase-data:/data
    ports:
      - "127.0.0.1:8082:8080"

volumes:
  gresbase-data:
      docker run -d --name gresbase \
  -e DATABASE_URL=postgres://USER:PASSWORD@HOST:5432/DBNAME \
  -e GRESBASE_READ_ONLY=false \
  -p 127.0.0.1:8082:8080 \
  -v gresbase-data:/data \
  --restart unless-stopped \
  ghcr.io/OWNER/gresbase:latest

    2. Point it at your database#

      Replace USER, PASSWORD, HOST and DBNAME in DATABASE_URL. If the password contains characters such as @, : or /, percent-encode them (@ becomes %40).

    3. Start it#

      Terminal
      docker compose up -d
docker compose logs -f gresbase

    4. Open Gresbase#

      Go to http://localhost:8082. The connection card at the bottom of the sidebar shows a green dot when Gresbase can reach your database.

    Browse without changing anything#

    Set GRESBASE_READ_ONLY to "true" to explore a production database safely. Every write action disappears from the interface and a Read-only badge shows in the sidebar.

    Keep the data volume#

    Gresbase keeps its own configuration in /data, including gresbase.json and the key that encrypts it. Your PostgreSQL data never lives there.

    Removing the volume (docker compose down -v) resets that configuration and signs everyone out.

    Configuration at a glance#

    VariableDefaultWhat it does
    DATABASE_URL—Connection string of the database to manage.
    GRESBASE_READ_ONLYfalseHides every action that writes to the database.
    GRESBASE_SESSION_SECRETGeneratedSigns sessions. If unset, it is generated once and saved in /data.
    GRESBASE_SECRET_KEYsecret.keyEncrypts gresbase.json. Changing it signs everyone out.

    All the options are in Environment variables.

    Next steps#

    • Take the quick tour of the main screens.
    • Write your first query in the SQL editor and run it with ⌘ ↵ (Ctrl ↵ on Windows and Linux).
    • Before opening it to your network, read Security and networking.

    Don’t publish port 8082 on every interface (0.0.0.0) without HTTPS in front. Anyone on the network could reach your database through it.

    Empezar /

    Inicio rápido

    Arranca Gresbase con Docker Compose y conéctalo a tu base de datos PostgreSQL en unos minutos.

    En esta página

      Antes de empezar#

      • Docker con Compose v2 (docker compose version debe responder).
      • Una base de datos PostgreSQL a la que llegue el contenedor y un usuario para conectarte.

      Si PostgreSQL corre en la misma máquina pero fuera de Docker, localhost dentro del contenedor no es tu máquina. Usa host.docker.internal en Docker Desktop o la IP del equipo.

      Instalar y arrancar#

      1. Crea el fichero de Compose#

        Guárdalo en una carpeta vacía. Si no usas Compose, la pestaña docker run hace lo mismo con un solo comando.

        services:
  gresbase:
    image: ghcr.io/OWNER/gresbase:latest
    restart: unless-stopped
    environment:
      DATABASE_URL: postgres://USER:PASSWORD@HOST:5432/DBNAME
      GRESBASE_READ_ONLY: "false"
    volumes:
      - gresbase-data:/data
    ports:
      - "127.0.0.1:8082:8080"

volumes:
  gresbase-data:
        docker run -d --name gresbase \
  -e DATABASE_URL=postgres://USER:PASSWORD@HOST:5432/DBNAME \
  -e GRESBASE_READ_ONLY=false \
  -p 127.0.0.1:8082:8080 \
  -v gresbase-data:/data \
  --restart unless-stopped \
  ghcr.io/OWNER/gresbase:latest

      2. Apunta a tu base de datos#

        Sustituye USER, PASSWORD, HOST y DBNAME en DATABASE_URL. Si la contraseña lleva caracteres como @, : o /, codifícalos para URL (@ pasa a ser %40).

      3. Arráncalo#

        Terminal
        docker compose up -d
docker compose logs -f gresbase

      4. Abre Gresbase#

        Entra en http://localhost:8082. La tarjeta de conexión, abajo en la barra lateral, muestra un punto verde cuando Gresbase llega a tu base de datos.

      Explorar sin cambiar nada#

      Pon GRESBASE_READ_ONLY a "true" para explorar una base de producción sin riesgo. Desaparecen todas las acciones de escritura y aparece el distintivo Solo lectura en la barra lateral.

      Conserva el volumen de datos#

      Gresbase guarda su propia configuración en /data, incluidos gresbase.json y la clave que lo cifra. Los datos de tu PostgreSQL nunca se guardan ahí.

      Si borras el volumen (docker compose down -v), esa configuración se pierde y se cierran todas las sesiones.

      La configuración de un vistazo#

      VariablePor defectoQué hace
      DATABASE_URL—Cadena de conexión de la base que vas a gestionar.
      GRESBASE_READ_ONLYfalseOculta todas las acciones que escriben en la base.
      GRESBASE_SESSION_SECRETGeneradoFirma las sesiones. Si no se define, se genera una vez y se guarda en /data.
      GRESBASE_SECRET_KEYsecret.keyCifra gresbase.json. Si cambia, se cierran todas las sesiones.

      Todas las opciones están en Variables de entorno.

      Siguientes pasos#

      • Haz el recorrido rápido por las pantallas principales.
      • Escribe tu primera consulta en el editor SQL y ejecútala con ⌘ ↵ (Ctrl ↵ en Windows y Linux).
      • Antes de abrirlo a tu red, lee Seguridad y red.

      No publiques el puerto 8082 en todas las interfaces (0.0.0.0) sin HTTPS delante. Cualquiera en la red podría llegar a tu base de datos a través de él.
